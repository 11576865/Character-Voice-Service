# CVS 基础设施风险审计（2026-10-11）

> **范围：源码与 GitHub CI 基础结构审计；不是运行中主机安全扫描，也不是 GPU 现场验收。**  
> 基线：CVS `main` 合并 PR #30 后的提交 `2d842f8e64ef199532cea61685da0179ffa6ccfd`。  
> 当前修复 PR：独立安全基础分支（提交时 CI Pending）。

## 审计准则

- **证据等级 A：** 源码中可以直接定位的实现或缺口（含明确的调用路径）
- **证据等级 B：** 独立 Linux/Windows GitHub CI 已运行、通过的自动化测试
- **证据等级 C：** 实机配置、用户网络、外部 System Supervisor、真实模型和 GPU 的现场验证
- 不得用 B 级模拟引擎验证冒充 C 级硬件与互操作验收。
- “已发现路径风险”与“现实环境已发生安全事件”必须区分。

## 本 PR 安全修复合同

1. 原有 `CVS_ADMIN_TOKEN` 环境变量覆盖机制保持不变；若环境变量设置了非空值，不接触文件令牌。
2. 没有环境令牌时，在同一 `CVS_DATA_DIR` 中使用 `O_CREAT|O_EXCL` 只有一个令牌创建者，其余 CVS 进程等待并读取相同文件。
3. 令牌落盘执行 `flush` + `fsync`，POSIX 上新文件权限为 `0600`，已有非私有权限令牌被修正但**不轮换内容**。
4. 发现符号链接、目录冒充文件或在限定等待时间后仍为空的令牌文件时，**拒绝继续启动**，不偷偷生成新的凭据覆盖旧状态。
5. 本机默认仅监听 `127.0.0.1`；需要 Android／Reader 跨设备访问时，管理员仍可显式设置 `CVS_HOST`，并需自己建立网络访问控制。
