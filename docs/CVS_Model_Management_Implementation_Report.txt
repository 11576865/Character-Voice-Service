CVS 本地语音模型管理、升级与引擎扩展实施报告
版本：1.0
日期：2026-09-28
性质：基于现有仓库代码的工程设计与实施说明

一、目标与决策

CVS 的模型管理需要补齐四个环节：Model Root 自动发现模型；Model Registry 保存模型身份、版本与生命周期；Evaluation 记录可复核的验证结果；Engine Adapter 对接不同推理引擎。四项共同服务于现有角色朗读、书库生成、段落修正、离线下载及成品导出。

目标体验是：训练结束后把模型放到已配置目录，扫描器发现新版本，登记为候选，使用统一样本进行评估，由用户选择是否提升为默认。日常升级不再要求手工修改角色 JSON、网页代码或推理接口路径。

这种自动化有明确边界：支持过的引擎和模型布局可以自动发现与接入；首次采用一种新引擎仍需要对应适配器、依赖环境和运行配置。仅保持本地仓库目录不变，不能自动解决模型格式或接口协议变化。

本报告采用保守默认：新模型不自动取代现有默认模型；“能生成”与“效果更好”分别记录；未进行真实推理或人工试听的项目必须标记未验证。根据此前用户决定，本轮基础设施实施使用代码与模拟测试，不自动开展真实 GPU 推理或试听实验。

二、现有代码事实与缺口

核验基线：feature/reader-library-offline 分支，任务总览提交 b792b91。

1. server/voice_profiles.py 已支持 schema_version=2 的角色配置。一名角色可以包含多个模型和参考语音，有 default_model 与 default_reference。模型解析目前明确限定为 gpt-sovits。
2. server/folder_import.py 能从角色目录导入 WAV，根据文件名的情绪前缀和逐字文本生成参考记录；已能匹配 v4、v2Pro 权重以及部分 _EN 文件名。
3. 现有导入器要求角色只有唯一匹配的权重对。多训练轮次或多格式同时存在时会拒绝，尚未形成候选模型版本库。
4. 当前模型 ID 如 v4-local、v2Pro-local 属于可变标签，不能唯一证明权重内容；用相同 ID 或相同路径替换权重，历史生成记录可能无法准确区分。
5. server/backends/gpt_sovits.py 把切换权重与生成置于同一锁内。已加载缓存使用两个文件路径作为身份，同路径替换文件是需要修复的升级边界。
6. Reader、书库、生成任务、段落版本、离线下载及导出已有基础实现。书籍保存声音设置，并依据生成指纹复用音频。模型 revision 必须贯穿这一流程，才不会错误复用旧版本。
7. 当前有九个真实角色配置；刻律德菈、昔涟此前发现了模型，但缺少可用参考语音，不能据此宣称角色已经可生成。
8. 已有评估相关测试和人工试听需求，但未形成统一 Evaluation 对象、完整候选生命周期或通用引擎注册机制。

“已有角色配置 v2”与“新增模型目录注册表”不是同一个数据文件。新增目录注册表从 schema_version=1 独立演进，避免把现有角色 v2 再次命名为 v2 而混淆迁移范围。

三、模型身份：角色、模型系列、内容版本与位置

character_id：稳定角色 ID，如 march-7th。显示名可修改，不改变身份。
model_id：逻辑模型系列，可描述一个角色的一条训练线；不作为权重内容身份。
revision_id：具体模型版本标识，由引擎、布局及组成模型的文件角色和 SHA-256 计算。路径、盘符和显示名不参与内容身份。
root_id：模型目录的逻辑名称，如 local-gpt-sovits。实际绝对目录存在本机配置。
artifact：模型组成文件，至少包含 kind、relative_path、size、sha256。GPT-SoVITS 通常是 gpt 与 sovits 两个 artifact；未来引擎可能是多个文件或整个模型目录的清单。

同一组权重移动到另一目录，应保持 revision_id；同一路径被覆盖且文件内容变化，必须产生新 revision_id。文件名上的 epoch、版本名或时间戳是描述信息，不能代替内容身份。

扫描过程中只进行 stat 检查时不能获得可靠 revision_id，此时保留未验证状态。仅文件大小或修改时间相同，不能证明内容未变。

推荐根目录配置（实际配置放 data/model-management/roots.json，不入库）：
{
  "schema_version": 1,
  "roots": [
    {"id": "local-gpt-sovits", "engine": "gpt-sovits", "path": "<本机安装根目录>"}
  ]
}

一个根目录可以包含 GPT_weights_v4、SoVITS_weights_v4、GPT_weights_v2Pro 等子目录。迁移盘符或整体移动时只改 root 的 path。引擎环境、服务地址、缓存目录是其他配置，不应从模型根目录位置自行猜测。

四、自动扫描与配对策略

扫描器首先输出报告，再由登记流程处理。它可以识别：配置目录不可用、文件不可读、单边权重、唯一权重对、多组无法确定的权重、已在角色配置中引用的权重对，以及未在角色配置中引用的权重对。

文件扫描状态与生命周期分开。第一阶段用 paired、ambiguous、incomplete、unrecognized、invalid 表达结构结果，用 registered、unregistered、missing、root_unavailable 表达与旧配置的关系。以后与注册表比对后才能可靠输出 new、known、changed；不能在没有历史指纹时虚构 changed 或 verified。

配对优先级：
1. 明确的模型 manifest，其内容指定每个组成文件、角色及语言。
2. 已有角色配置明确写出的 GPT/SoVITS 对，仅代表已知关联，不代表质量合格。
3. 同一布局、同一名称只有一个 GPT 文件和一个 SoVITS 文件时，作为待确认的唯一结构候选。
4. 同名有多轮权重时，列出全部文件并标为 ambiguous。不能把 GPT epoch 10 与 SoVITS epoch 10 自动认为同一次最佳组合；两个训练阶段可能独立选择轮次。

扫描中不反序列化模型权重、不启动引擎、不执行模型目录里的脚本。完整哈希采用流式读取，避免一次把数 GB 权重载入内存。哈希前后核对文件状态，训练正在写入时标记为不稳定，下次重试。

目录中的软链接、junction 或相对路径必须在解析后保持在配置根目录内。外部链接不自动追踪。模型目录不可用时保留注册记录；可移动磁盘暂时离线不应触发模型退役或删除。

大型目录不能每次网页打开都全量哈希。后续引入可失效的指纹缓存、后台扫描任务及进度；轻量扫描用于发现变化，完整哈希用于登记和启用核验。对同大小同时间戳的文件，轻量扫描仍只能给出未完全验证结论。

五、Registry 生命周期与可用性

生命周期：candidate / default / retired。
可用性：unknown / available / missing / invalid / engine_unavailable。
两组字段独立保存。例如 default + missing 表示原默认模型文件暂时缺失，不能把生命周期自动改成 retired。

candidate：新发现并登记的候选，可显式选择进行评估。普通 Reader 或整书任务不得隐式采用候选。
default：某个已明确的使用范围的默认版本。第一版范围先定义为角色与目标语言；引擎是模型属性。将来确实需要同角色按引擎保留不同默认时，再显式扩展 scope，不能同时存在多个没有优先级的默认项。
retired：不再作为新内容的自动默认选择，但保留元数据、历史引用及已有音频。用户明确固定此 revision 的旧书可按策略继续复现；不可把退役等同于不可读取或物理删除。

允许操作：登记候选、提升默认、退役非当前默认、恢复候选、回退默认。每次操作记录时间、操作者、理由、前后默认版本及相关 Evaluation ID。

提升应是一次事务：验证文件与参考条件 → 检查范围和当前 revision → 写审计事件并更新唯一默认指针 → 更新兼容映射。事务失败必须保持原默认一致。多文件分别覆盖不是真正原子操作；第一阶段采用单一权威目录文件加原子替换，规模扩大后考虑 SQLite 事务。

活跃任务提交时固定实际 revision；任何正在使用模型的任务不能受默认指针改变影响。初期最容易验证的行为是存在活跃生成或评估请求时拒绝相关默认切换；后续可允许指针变化但任务继续使用已固定版本。实现必须覆盖 Reader 实时请求，不能只检查整书任务字典。

不自动清理退役权重。将来清理时先列出书籍、任务和评估依赖；元数据保留与文件清理是独立操作。

六、书籍绑定与缓存一致性

书籍模型策略：pinned 固定 revision；follow_default 跟随角色默认。

旧书迁移优先固定迁移时实际可核验的版本。旧文件已经被覆盖、无法证明历史内容时必须标记 legacy_unverified；不能给过去的音频补造一个看似准确的新 revision。

follow_default 在提交任务时解析一次，并把结果写入该任务快照。生成一章期间升级默认不能导致前后段落使用不同版本。再次生成时若默认已变化，界面显示哪些音频需要更新。

音频复用指纹应至少包含：实际文本及发音修正规则版本、引擎/适配器版本、模型 revision、参考音频内容指纹、参考逐字文本与语言、有效生成参数、输出规格。若有随机种子，记录实际支持和采用的值；引擎不支持时留空，不能假装设置已生效。

权重切换缓存也要使用 revision，不仅是文件路径。最终的 load + synthesize 必须由适配器提供整体操作并维持引擎锁；上层把两步分开调用会重新引入竞争。

段落最多七个版本、用户选定版本、离线音频及已导出文件仍保持各自历史。修改默认不会改写已下载音频。需要新声音时执行重生成与重新下载/导出。

七、统一 Evaluation v1

Evaluation 是一次可回溯实验记录。它与生产任务有关联，但不应覆盖生产书籍，也不能只存一个总分。

建议字段：
schema_version、evaluation_id、created_at、started_at、finished_at；
character_id、candidate_revision_id、baseline_revision_id；
sample_set_id、sample_set_version、sample_set_sha256；
reference_set_id、每条实际参考的音频/文本指纹；
engine_id、adapter_version、可取得的引擎 commit 或包版本、运行环境摘要；
requested_parameters、effective_parameters、unsupported_parameters；
status、每个样本的输入、输出 artifact、失败类型、耗时和音频规格；
human_reviews、decision、decision_reason、reviewed_at。

样本记录至少包含 sample_id、text、language、category、reference_id、model_revision_id、status、audio_artifact_id、audio_sha256、queue_ms、load_ms、synthesis_ms、audio_duration_ms、real_time_factor、error_code、error_message。无法可靠拆分的计时字段留空，说明计时边界。

样本集合先提供短句、长段、数字/专名、中英混合、情绪、连续段落六类。样本文本应固定且可版本化；使用项目原创文本，避免把私人书籍当成公开测试集。模型只声明支持某语言时才安排对应语言测试，unsupported 不能记为质量失败。

自动检查先覆盖请求完成、有效音频、时长、音量异常提示、失败率、等待时间及重复运行稳定性。静音阈值或异常短音频只是排查信号，不能直接替代人工发音和音色判断。ASR 字错率等后续指标引入时必须保存工具版本、语言和规范化规则；不同工具分数不能直接混排。

人工评分区分音色一致性、发音完整性、自然度、情绪匹配及段落衔接。建议 1–5 分并定义含义，允许不适用和未评估。保留具体错误文本和评论。总评分权重若引入，必须明确公开且有版本。

A/B 试听需隐藏模型名、随机左右顺序并保存映射。可选 A 更好、B 更好、相近、两者均有问题。重复听同一音频应重播记录的 artifact，不重新生成随机样本。

基础通过、人工接受和默认提升是三个独立结果。评估成功完成不等于候选更好；记录不完整时可保存 draft，不能自动标记 passed。用户可以带理由手动提升，但应在审计中明确尚缺哪些验证。

八、Engine Adapter 与替换开源引擎

接口围绕稳定生成请求：角色、revision、文本、目标语言、参考输入、速度与可支持的生成参数。返回音频、实际模型版本、实际参考和参数、计时及规范化错误。

建议能力：discover / validate / capabilities / health / synthesize。synthesize 内部负责模型准备、切换锁及推理。独立 prepare 可以用于预热，但不能让上层依靠“先 load 再 synthesize”来保证正确性。

能力表应说明：支持语言、参考音频方式、是否要求逐字文本、是否需要说话人 embedding、是否支持速度/种子/流式、输出格式、共享模型是否能并发。缺少能力时界面禁用相应控件，并说明原因；不能静默丢弃用户参数。

更换引擎可能还需要参考预处理、音频采样率转换、说话人条件注册以及依赖环境。一个角色可以对应多个引擎的模型，但不同引擎的参考输入未必直接互换。每种引擎第一次接入都要有适配器与小规模验证。

模型仓库、推理环境和 CVS 分开配置。为每个引擎保存 engine_id、服务地址、启动方式或外部服务说明、版本、model root IDs。第一版以已有 GPT-SoVITS 服务为适配对象；不自动下载新引擎，不自动执行发现的安装脚本。

目前本报告没有声称任何未接入引擎已兼容；新引擎的具体接口与许可应在正式选择时检查其官方仓库和文档。

九、文件布局与隐私

可提交 GitHub：扫描器、适配接口、格式定义、迁移代码、示例配置、原创样本、测试及本报告。
仅本机 data/model-management/：roots.json、registry.json、scan-report.json、audit 记录、evaluation 元数据与音频。模型继续保留原目录；角色实际配置和参考语音继续遵守现有忽略规则。

完整扫描报告包含本地目录和模型文件名，只放本机。公网网页只向已登录用户提供管理信息，普通角色列表不暴露绝对路径。上传问题或评估摘要到 GitHub 前使用去路径、去私人文本的摘要。

备份以 registry、roots、本机角色配置和评估元数据为核心；权重与参考音频另有资产备份策略。临时缓存可重建，评估结论与映射不可随意清理。根目录配置移动到另一台电脑后允许重新映射。

十、兼容迁移与回退

阶段一只读盘点，扫描不修改角色或书籍。已登记路径只作为关联证据，完整哈希后再确定 revision。
阶段二生成迁移预览：每个旧角色 model_id 对应的 revision、默认项、无法读取项及未管理的 loaded 模型。外部已加载模型不能凭空生成 revision，继续标记 unmanaged。
阶段三备份并登记目录；保持旧角色接口的兼容映射。新的消费者使用 revision，旧字段在过渡期由同一权威数据派生，避免两套默认各自变化。
阶段四让生产任务和实时 Reader 保存实际 revision；确认复用判断与迁移测试通过后，再开放默认提升。
回退不删除新记录：恢复原默认指针及兼容配置，保留升级和回退事件；已生成的新音频仍可播放。扫描器和评估工具故障不能阻止已有固定模型朗读。

十一、实施阶段与验收

E1 数据约定与只读扫描（本轮首先落实）
产物：本报告、逻辑根目录示例、扫描命令、结构化报告、针对边界的测试。
验收：现有角色关联可识别；多个 epoch 不乱配；缺失和越界路径报出；重复扫描无数据修改；可选完整哈希对改名保持身份、对内容变化改变身份。

E2 候选注册与持久目录
产物：Registry schema、原子写入、legacy 预览和迁移、幂等登记、审计记录。
验收：同一 revision 不重复；错误写入不破坏旧目录；candidate 不覆盖 default；暂时缺失不删除记录。

E3 统一 Evaluation 存储和评估任务
产物：固定样本集、统一记录校验、候选/基线任务、取消/恢复和 A/B 界面。
验收：失败可定位；参数和输出可回溯；断点恢复不更换模型或样本；评分可保存。真实质量验收等用户恢复实测后进行，代码测试通过不能代替试听。

E4 生产 revision 接入与默认提升
产物：书籍 pinned/follow_default、任务快照、缓存指纹迁移、原子提升/回退、活动请求约束。
验收：升级后新任务采用正确版本；旧任务不混用；同路径替换不会误用缓存；缺失版本有明确恢复方式；段落七版本行为不回归。

E5 GPT-SoVITS 适配层收束
产物：通用生成请求/响应、能力声明、统一错误、现有后端适配。
验收：现有角色生成协议不变，模型切换与推理仍串行；不支持的参数可见；模拟第二适配器证明上层不依赖 GPT 专属字段。
说明：适配契约在 E1–E2 预先约定，具体重构分步进行；不能等所有生产功能写死 GPT 字段后再重新抽象。

E6 管理网页与启动轻量扫描
产物：根目录状态、候选列表、扫描进度、评估入口、提升/退役/回退入口和启动提示。
验收：鉴权有效；多个扫描不竞争；扫描失败可重试；不阻塞启动；不自动提升；显示未验证项。

E7 第二个真实引擎验证
前提：选择具体引擎并确认机器资源、许可及模型支持范围。
产物：新适配器、独立环境配置、能力映射、参考兼容处理。
验收：同一本短文能通过两个适配器生成；Reader/整书/导出无需引擎专用改动；限制和质量差异有评估记录。

各阶段以可审查提交和必要测试收束。已有朗读、整书、离线及导出主线继续使用这些底层能力；Android System TTS、环境音混音和手机本地大模型仍保持原优先级。

十二、关键测试清单
