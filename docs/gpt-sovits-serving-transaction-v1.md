# GPT-SoVITS serving transaction safety v1

## Source-confirmed failure boundary

Before this change, `server/backends/gpt_sovits.py` used a Python
`threading.Lock` and process-local `_active_managed_model` cache.
Two CVS instances sharing one GPT-SoVITS backend were **not** protected
from cross-process weight-switch interleaving. A backend restart could
also invalidate the real loaded weights while CVS retained the old
cache and incorrectly skipped switching.

The Runtime Supervisor's GPU-slot OS lock governs **backend process
launch ownership**, not the `/set_sovits_weights` ->
`/set_gpt_weights` -> `/tts` serving transaction.

## Bounded repair

For every GPT-SoVITS synthesis request, CVS now:

1. Resolves and **freezes the TTS/control endpoint triple once**,
   preventing configuration reload between weight switching and TTS.
2. Takes the existing thread mutex and a **nonblocking cross-process
   OS file lock** in `CVS_DATA_DIR/inference-transactions/`, with a
   group key derived from SHA256 of the normalized TTS URL. The lock
   is held throughout the *entire* model switch plus `/tts` response.
   Concurrent requests from a different CVS instance to the same
   endpoint return HTTP 503 with Retry-After rather than switching
   weights while the first is generating.
3. Under the lock, persists a **pending inference intent** with a
   unique request ID, selected model ID and endpoint before touching
   backend weights or submitting inference.
4. For managed GPT-SoVITS models, explicitly sets **both** SoVITS
   and GPT weights on **every** serving transaction. A process-local
   cache is not a trustworthy backend-epoch signal. This intentionally
   sacrifices cached switch performance until the actual backend
   exposes a verifiable model+epoch attestation protocol.
5. Sends `/tts` under the same lock, then clears only the matching
   pending receipt after a normal HTTP response read, before releasing
   the lock.
6. On timeout, process death, interrupted HTTP I/O or any other
   ambiguous failure after receipt publication, leaves the receipt
   intact. Another CVS instance can acquire the OS lock after the
   first dies, but **must not issue a new model switch or inference**
   until an operator checks that the old backend has finished and
   reconciles the specific pending intent under the same OS lock.

This is an **at-most-one-cooperating-CVS-inference-admission**
boundary. It is not a promise that an actual GPT-SoVITS server
enforces exclusive model residency or that generated bytes correspond
to the expected human speaker without deeper backend attestation and
audio verification.

## Operational consequences

A second CVS worker sharing one endpoint now receives a retryable
503 while another synthesis is in flight instead of queuing the request
and risking cross-process identity drift. The old
`_active_managed_model` variable remains for legacy same-process
external-model safety, but is **never used to skip** a managed model
load after backend restart.

A persistent `*.pending.json` record blocks further requests until
explicitly reconciled. This is intentional **fail-closed behavior**:
HTTP connection loss does not prove that the GPU stopped generating.
No automatic TTL cleanup, stale deletion, or inferred success is
introduced. Do not delete `*.lock` files: removing a held lock file
can create split-brain owners. Operators must confirm the actual
backend PID/process tree, no in-flight TTS work, model state and request
identity, then manually reconcile the pending receipt while holding
its endpoint lock. The file is not a consumer acknowledgement and
does not by itself prove correctness of model selection.

All cooperating CVS instances must resolve the **same endpoint URL**
and share one filesystem data root/transaction-lock directory. A
different data directory, external direct GPT-SoVITS client, remote
System Supervisor or non-cooperating script can still switch weights.
This v1 does **not** protect inference against a sibling GPU engine's
independently initiated lifecycle stop. That requires an end-to-end
cross-runtime inference-admission/drain contract.

## Verification

- Existing `tests/test_gpt_sovits.py` tests are updated to assert
  both managed weights are reapplied for repeated requests and after
  a simulated backend state reset. A prior-inference timeout must
  retain the receipt and block replay.
- `tests/test_gpt_sovits_transactions.py` runs actual **independent
  CVS Python worker processes** against a disposable real local
  HTTP server. It holds A's inference open while B attempts a model
  switch, then validates retryable refusal; it also **kills the CVS A
  process** mid-inference and verifies that a new CVS B cannot switch
  models merely because the OS lock has been released.
- Windows targeted CI now includes both GPT-SoVITS test files and
  `tests/test_contract.py`, closing a core Windows coverage gap.

## Still unproved (must not be claimed as passed)

- Actual GPT-SoVITS model weights, speaker identity and GPU-level
  consistency have not been exercised in this mock integration.
- Model selection by **external/unmanaged** GPT-SoVITS clients cannot
  be validated by this local coordination protocol. Legacy external
  model behavior remains a separate risk pending backend attestation.
- Inference shutdown/drain when changing to another `exclusive_group`
  engine is not solved in this PR.
- Valid/decodeable WAV and audio content identity are separate source
  defects; they still need a strict centralized response validator
  and real audio acceptance tests.

**CI must succeed on the final PR head on Linux and Windows before
merging. Hardware and real model acceptance remain FIELD-PENDING.**
